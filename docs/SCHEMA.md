# Схема данных

## Слои

Репозиторий разделён на редакторский и исполняемый слои:

```text
справочники + content + rules + runtime-config
                        ↓ generate-runtime.mjs
                 runtime/<collection>.json
```

Runtime всегда генерируется и не редактируется вручную.

## Справочник действий

`data/catalogs/actions.json` содержит массив `actions`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string | Стабильный собственный идентификатор |
| `preferredNameRu` | string | Название для интерфейса |
| `kind` | string | Лекарство, процедура, решение, коммуникация или другой тип |

## Справочник исследований

`data/catalogs/studies.json` содержит единый массив `studies`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string | Стабильный собственный идентификатор |
| `preferredNameRu` | string | Российское название исследования |
| `kind` | string | Лабораторное, лучевое, функциональное или прикроватное исследование |
| `externalCodes` | array | Сопоставления с НМУ и точность `relation` |
| `fsliCode` | string \| null | Код ФСЛИ либо явное отсутствие подтверждённого сопоставления |

## Контент коллекции

`data/cases/<collection>/content.json` хранит только содержание предъявления:

- `id`, `title`;
- `patient`;
- `presentation` с жалобой, показателями и анамнезом;
- `studyResults` — результаты по собственным ID исследований.

Результаты являются закрытой частью сценария и не должны передаваться клиенту до назначения исследования.

## Правила коллекции

`rules.json` содержит диагноз, `actionRules`, `studyRules`, ссылки на рекомендации, статус аудита и ссылку на его раздел.

Классы оценки:

| Значение редакторского слоя | Группа runtime | Смысл |
|---|---|---|
| `required` | `required` | ожидается всегда |
| `conditional` | `conditional` | ожидается только при истинном условии |
| `optional` | `optional` | допустимо, но не обязательно |
| `not-routine` | `avoid` | требуется отдельное обоснование |
| `unscorable-as-specified` | `avoid` | действие недостаточно конкретно |
| `unsafe-or-delaying` | `unsafe` | опасно или задерживает приоритетную помощь |

Правило действия задаёт показание, проверяемые условия, противопоказания, способ выполнения и критерий ответа. Для лекарства обязательны доза, путь и время. Правило исследования задаёт время, обоснование и помощь, которую оно не должно задерживать.

## Runtime-конфигурация

`runtime-config.json` содержит начальные `facts`, пояснения, условия для всех правил класса `conditional` и `choiceGroups`.

Условие `when` имеет одну из форм:

```json
{"always": true}
{"fact": "patient.spo2", "op": "lte", "value": 92}
{"all": [{"fact": "stabilized", "op": "eq", "value": true}]}
{"any": [{"fact": "pregnancy", "op": "eq", "value": true}]}
{"not": {"fact": "contraindication", "op": "eq", "value": true}}
```

Доступны операторы `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in`, `exists`. Результат равен `true`, `false` или `null`, если факта пока нет. После изменения состояния пациента приложение пересчитывает условия.

`choiceGroups` ограничивает число выбираемых альтернатив полями `minSelections` и `maxSelections`.

## Runtime

`runtime/<collection>.json` содержит `_meta` и `cases`. В каждый случай встроены:

- пациент и предъявление;
- начальные факты;
- диагноз;
- полностью разрешённые действия и исследования;
- машинные условия и их начальное значение `applicableNow`;
- закрытые результаты исследований;
- группы выбора и ссылки на рекомендации.

Контрольные суммы входных файлов записываются в `_meta.inputSha256`. Благодаря отсутствию времени генерации одинаковые входные данные дают побайтно одинаковый runtime.

## Инварианты

- все основные ID являются собственными и уникальными;
- внешние идентификаторы происхождения не входят в данные репозитория;
- ссылки на действия, исследования и рекомендации разрешаются;
- каждое условное правило имеет одно машинное условие;
- безусловное правило не имеет скрытого условия;
- каждое исследование сценария имеет результат;
- runtime соответствует текущим входным файлам;
- клинический статус нельзя выводить из успешной структурной проверки.
